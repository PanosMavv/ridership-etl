# Ridership + Weather ETL Pipeline

A modular, resilient Python CLI that ingests raw public-transport ridership
data (CSV) and daily weather data (SQLite), cleans and merges them, performs
EDA, and outputs charts + a structured JSON summary.

## Project layout

```
ridership-etl/
├── .env                  # default configuration (CSV/DB paths, output dirs)
├── main.py               # CLI entry point (argparse, logging, exit codes)
├── config.py             # PipelineConfig dataclass + .env loading
├── data_pipeline.py      # DataPipeline: extract / transform / merge / load
├── analysis.py           # metrics + AnalysisResult (JSON-serialisable summary)
├── visualizer.py         # line chart + heatmap (matplotlib/seaborn, Agg)
├── make_sample_data.py   # generates demo ridership.csv + weather.db
├── requirements.txt
├── Dockerfile
├── ridership.csv         # generated by make_sample_data.py
├── weather.db            # generated by make_sample_data.py
├── processed_ridership.db  # output SQLite (table: processed_ridership)
├── output/               # charts + summary.json
├── etl_pipeline.log      # full run log
└── tests/
    └── test_pipeline.py
```

## Requirements

Python 3.10+. Install dependencies:

```powershell
python -m venv .venv
.venv\Scripts\activate          # Windows; use `source .venv/bin/activate` on macOS/Linux
pip install -r requirements.txt
```

## Configuration

Defaults live in `.env`:

| Variable          | Meaning                                  | CLI override        |
|-------------------|------------------------------------------|---------------------|
| `RIDERSHIP_CSV`   | input CSV path                           | `--input-csv`       |
| `WEATHER_DB`      | weather SQLite path                      | `--weather-db`      |
| `OUTPUT_DIR`      | charts + summary output                  | `--output-dir`      |
| `PROCESSED_DB`    | output SQLite for cleaned data           | `--processed-db`    |
| `LOG_FILE`        | log file (default `etl_pipeline.log`)    | `--log-file`        |

## Running

Generate demo inputs (optional):

```powershell
python make_sample_data.py
```

Run the pipeline:

```powershell
python main.py --input-csv ridership.csv --output-dir output
```

Or with just the `.env` defaults:

```powershell
python main.py
```

**Outputs**

- `output/total_passengers_per_day.png` — line chart of daily ridership
- `output/passenger_volume_by_hour_and_dow.png` — hour × day-of-week heatmap
- `output/summary.json` — highest ridership day, average daily ridership,
  precipitation↔ridership correlation (plus peak/off-peak hour stats)
- `processed_ridership.db` → table `processed_ridership` — cleaned + merged data
- `etl_pipeline.log` — every major step, at INFO level

**Expected inputs**

- `ridership.csv` columns: `trip_id`, `station_id`, `timestamp` (`YYYY-MM-DD HH:MM:SS`),
  `ticket_type`, `passenger_count`
- `weather.db` table `daily_weather` columns: `date`, `temp_c`, `precipitation_mm`

## Data cleaning rules

- Rows with missing/non-numeric `passenger_count` are dropped.
- Missing/empty `ticket_type` values become `"Unknown"`.
- Unparseable `timestamp`s are dropped; `date`, `hour`, `day_of_week` are derived.
- Weather rows with unparseable dates are dropped.
- Datasets are merged on `date` with a left join (ridership rows are always kept).

**Peak hours:** `7, 8, 9, 10, 16, 17, 18, 19` (changeable in
`config.DEFAULT_PEAK_HOURS`). "Average passengers per hour" = mean of the
per-hour passenger means within the peak (or off-peak) slice.

## Docker

```powershell
# build
docker build -t ridership-etl .

# run with a local volume (your folder must contain ridership.csv + weather.db)
docker run --rm -v C:\data:/data ridership-etl
```

macOS/Linux: `docker run --rm -v ./my_data:/data ridership-etl`

Charts land in the mounted volume under `/output` (i.e. `my_data/output`).

## Tests

```powershell
python -m pytest -v
```

Tests create an in-memory SQLite database (via a SQLAlchemy `sqlite://` engine)
and dummy DataFrames to exercise cleaning, merging, load, correlation, and
error paths.

## Exit codes

| Code | Meaning                                        |
|------|------------------------------------------------|
| 0    | success                                        |
| 1    | pipeline failure (missing file/columns, etc.)  |

All failures are logged to the console and `etl_pipeline.log` with clear
messages — no raw Python tracebacks.
